# Ballon d'Or — Votes

Расширение Chrome, которое показывает рейтинг из ответов API голосования.

## Установка

### Из готового релиза GitHub

1. Открой [последний релиз](https://github.com/maxim760/ballondor-boat-chrome-extension/releases/latest).
2. В разделе **Assets** скачай `ballondor2026-1.0.1.zip` — это готовое расширение.
3. Распакуй архив в постоянную папку, например `Documents/Extensions/ballondor`.
4. Открой `chrome://extensions`, включи **«Режим разработчика»** и нажми
   **«Загрузить распакованное расширение»**.
5. Выбери распакованную папку с `manifest.json`.
6. Открой [страницу голосования](https://ballondor.com/vote) и перезагрузи её.
   Справа сверху должна появиться плашка **Ballon d’Or · Голоса**.

Node.js, исходный проект и локальная сборка для этого не нужны.
Не удаляй распакованную папку: Chrome использует файлы из неё.
Если уже установлена копия из папки разработки, отключи её, чтобы не было двух панелей.

### Из исходников

1. Открой `chrome://extensions` в Chrome.
2. Включи «Режим разработчика».
3. Нажми «Загрузить распакованное расширение».
4. Выбери папку `ballondor2026`, содержащую `manifest.json`.
5. Открой [страницу голосования](https://ballondor.com/vote) и обязательно перезагрузи её.

## Использование

Справа сверху появится маленькая плашка. Нажми на нее, чтобы раскрыть
полный рейтинг. Длинный список прокручивается внутри панели.
По умолчанию список свернут. Ошибки обозначаются красной надписью
«Ошибка» даже в свернутом виде; подробности — внутри панели.
Если сайт загрузит несколько опросов, появится переключатель.
После изменения файлов нажми кнопку обновления расширения в `chrome://extensions`,
затем перезагрузи страницу сайта.

## Сборка

Нужен Node.js 20+ и утилита `zip` (в macOS встроена). Зависимостей нет,
`npm install` не нужен.

```sh
npm run build
```

Команда сначала запускает проверки, затем создает:

- `dist/unpacked/` — папку для кнопки «Загрузить распакованное расширение».
- `dist/ballondor2026-1.0.1.zip` — архив для передачи или загрузки в Chrome Web Store.
  Версия в имени берется из `manifest.json`.

ZIP напрямую через «Загрузить распакованное расширение» не устанавливается:
сначала распакуй архив и выбери полученную папку либо сразу выбери `dist/unpacked`.
После изменения кода выполни сборку повторно, обнови расширение в
`chrome://extensions` и перезагрузи сайт.

В пакет попадают только манифест и JS-файлы расширения. ZIP не означает,
что оформление страницы Chrome Web Store и модерация уже выполнены.

## Как устроено

| Файл | Назначение |
| --- | --- |
| `manifest.json` | Manifest V3, запуск при `document_start` |
| `interceptor.js` | MAIN world, наблюдает `fetch` и `XMLHttpRequest` |
| `ranking.js` | `getTopVotes` и `getYear` |
| `panel.js` | ISOLATED world, панель в Shadow DOM |
| `tests/check.cjs` | Проверки перехвата и обработки ошибок |
| `scripts/build.cjs` | Сборка папки для Chrome и ZIP |

Фильтр: HTTPS, точный домен `voting.fansunitedapi.com`, сегмент `/polls` в пути.
Читается `data.options`. Для `fetch` используется `response.clone()`: исходный ответ
остается у сайта. Дополнительные запросы к API расширение не отправляет.
Данные хранятся только в памяти текущей страницы.
Права ограничены `ballondor.com` и `www.ballondor.com`. Запуск на всех путях
этих доменов нужен для перехода на `/vote` без полной перезагрузки страницы.

В `getTopVotes` сохранен формат `[строка, исходный item]`. Сортировка не меняет
исходный массив. Перехватчик передает `data.options` без преобразований.
Обработчик сообщения проверяет только, что `options` — массив; структуру
элементов считаем правильной. Исключения обрабатывает общая обертка `try/catch`.
`getYear` дважды разбирает HTML через `div`, затем берет первое слово
из первого `<p>`, как в исходном маппере. Если его нет, возвращает `unknown`.
Данные в панель выводятся через `textContent`.

## Ограничения

Перехватываются только fetch/XHR в основном окне после запуска расширения.
Запросы из Web Worker, другого iframe, серверный рендеринг или смена API
могут потребовать другой способ перехвата. Если `votes` отсутствует или скрыт
самим API, расширение не может восстановить эти числа.
Панель показывает данные ответа, а не независимо проверенные результаты.
Разные URL query для одного пути считаются одним опросом, используется
последний полученный ответ; пагинация автоматически не объединяется.

[Документация Chrome: content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts).

Проверка на реальном API требует установки расширения в Chrome.
